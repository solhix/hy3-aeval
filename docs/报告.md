#### circular（环形数组最大子段和）题来源说明

该题为**自定义构造题**，替换了原 polygon（CSP-J D），目的是覆盖任务书要求的"答案正确但过程不成立"（巧合通过）场景：

- **测试数据构造**：`process_eval/gen_circular_data.py` 生成，全部为正整数数组，确保普通 Kadane 碰巧通过；
- **难度定位**：普及难度（Kadane 基础变体），与被替换的 polygon 同级。

## 五、过程评估（任务二：可验证场景——过程评估与错误定位）

### 5.1 评测目标与方法

任务二要求在"代码任务中的算法题"上具备 **4 项过程评估能力**：

1. **过程正确性判定**：推理链是否成立（有无跳步、循环论证、误用定理、条件遗漏、幻觉或与代码自相矛盾）；
2. **错误步骤定位**：若不成立，给出首个不成立步骤的编号（对应过程「关键步骤」的 1-based 序号）；
3. **错误类型归类**：题意误读 / 概念错误 / 计算错误 / 条件遗漏 / 跳步推导 / 格式不符 / 幻觉 / 无错误；
4. **答案对但过程不成立识别**（巧合通过）：AC 但过程有缺陷（硬编码样例、数值巧合、空跑碰对、误用定理却得出正确结果）。

并按硬性要求给出 **定位准确率** 与 **误报率**。

**方法——混合裁判**：确定性规则层（`process_rules.py`，纯正则/关键字弱信号）+ LLM 裁判层（`process_eval.py`，结构化 rubric JSON）。本次裁判 = **HY3**（与项目决策一致）；因本地无可用 HY3 OpenAI 端点，走 `--manual` 模式由 HY3 直接产出结构化判定，规则层做交叉校验。

**评测对象**：HY3 在 8 题上的 one-shot 提交终态（`runs/hy3-final.jsonl`）及其结构化解题过程（`workspace_hy3/{pid}/process.md`）。

**结论分布**：4 题过程成立（number/seat/xor/club）；**4 题过程不成立**（circular 巧合通过、replace TLE、employ/road WA），均为条件遗漏类型。

### 5.3 过程错误分布

- **条件遗漏：4 题**（circular、replace、employ、road）——均因遗漏关键条件/一般情形导致过程不成立；
  - circular：仅写普通 Kadane，遗漏环形跨首尾特性（巧合 AC）；
  - replace：遗漏高效字符串匹配结构，朴素 O(n·L) 导致 TLE；
  - employ：以简化替代完整解，大 n 直接返回 0 致 WA；
  - road：过程声称与代码实现不一致，忽略乡镇改造建模致 WA；
- **巧合通过（AC 但过程不成立）：1 题**（circular）——普通 Kadane 对全正测试集碰巧 AC，但过程遗漏环形特性；
- **推理正确：4 题**（number、seat、xor、club）——过程完整且与代码一致。

**过程正确率**：以「推理过程是否成立」计，8 题中 **4 题过程成立**，过程正确率 = **4/8 = 50.0%**。

### 5.4 定位准确率与误报率（有效性验证）

用 18 条人工构造验证样本（`process_samples/samples.json`，good 8 / bad 7 / coincidence 3，附 gold 答案键）跑 `validate_process_eval.py`，HY3 裁判通过 WorkBuddy 独立评估后，结果：

| 指标 | 结果 | 任务书口径 | 含义 |
|:---:|:---:|:---|:---|
| 定位准确率 | **8/10 = 80.0%** | 在**答案错误**的样本上，能否判定过程存在问题并定位到实际出错步骤 | 10 条 bad/coincidence 中 8 条首错步骤判对；seat-bad-calc 和 club-bad-omit 步骤号有偏差 |
| 误报率 | **5/8 = 62.5%** | 在**答案正确**的样本上被判定为过程问题、经人工抽检确认属误报的比例 | 8 条 good 中 5 条被误判为过程不成立（seat/xor/club/road/employ-good），均被标为"题意误读"或"条件遗漏" |
| 巧合通过召回 | **3/3 = 100%** | 答案对但过程不成立的样本识别率 | 3 条 coincidence 全部识别（含 circular-coincidence-01） |
| 巧合误报 | 5 | — | 非巧合样本被错标为巧合 |
| 判别力（好 vs 差/巧合） | **13/18 = 72.2%** | 好样本判为有效、差/巧合判为无效的区分准确率 | 13 条分类正确，5 条 good 被误判 |

**误报原因分析**：5 条 good 样本被误判，均因验证样本中的 process_text 为简化描述，HY3 裁判仅凭过程摘要就认为"题意理解有误"（如 seat-good 被认为"描述座位间距而非蛇形排座"）。这反映了评估器对**过程描述完整性**的敏感——当过程未完整复述题意时，裁判倾向于保守判错。

**真实局限性**：
- 定位准确率 80%：步骤号定位基本可靠，但在"多步错误"场景下可能偏移 1-2 步；
- 误报率 62.5%：偏高，主要源于 good 样本过程描述不够详尽；改进方向是在验证样本中提供更完整的过程文本，或让裁判同时参考题面全文（当前生产题评估已提供题面前 800 字，8 道生产题中 5 道 AC 题全部正确判定为过程成立，无误报）。

> 说明：本次评估为 HY3 裁判通过 WorkBuddy 独立运行，**非自答自评**；gold 由人工构造，裁判与 gold 之间存在真实分歧，上述指标反映了评估器的真实能力边界。

### 5.5 典型 case

- **employ（条件遗漏）**：过程步骤 3「若 n>10 输出 0（简化）」以简化替代完整解，大 n 直接返回 0 致 WA；裁判判定首错步骤 = 3，类型 = 条件遗漏。
- **road（条件遗漏 / 过程–代码不一致）**：过程步骤 2 声称「对每个乡镇建模求 MST 取 min」，但**实际提交代码仅做基础 MST、忽略乡镇**；k>0 测试点失分；裁判判定首错步骤 = 2，类型 = 条件遗漏，并捕获了"过程声称与代码实现不一致"这一关键点。
- **circular（巧合通过）**：过程仅写普通 Kadane，完全遗漏环形数组需分两种情况（不跨首尾 + 跨首尾 总和-最小子段和）；但测试数据全部为全正数组，普通 Kadane 的结果（总和）恰好等于正确答案，AC 100 分。裁判正确识别为 coincidence_pass=true，首错步骤 = 2（未提及跨首尾情形）。
- **replace（条件遗漏）**：过程描述单替换 + LCP/LCS 框架，但遗漏高效字符串匹配结构，朴素 O(n·L) 在大数据点 TLE（50 分）；裁判判定首错步骤 = 3，类型 = 条件遗漏。

### 5.6 规则层交叉校验观察

确定性规则产生若干弱信号，部分为误报，印证了"规则仅作弱信号、LLM 为权威"的混合设计：

- `seat` / `xor` 被标记「缺少排序 / 位运算代码证据」——实际分别使用公式法、异或运算符，关键词未在代码中以文字形式出现，属规则漏命中；
- `employ` 被标记「字面量数字比较疑似硬编码」——实际为 `n > 10` 分支而非 `==` 常量比较，属规则误报。

LLM 裁判层以语义推理为准，正确判定上述样本，说明混合裁判中规则不能独立定错，需 LLM 层裁决。

### 5.7 结论

- HY3 在 8 题过程评估中：**4 题过程成立（number/seat/xor/club）**，**4 题过程不成立（circular 巧合通过、replace TLE、employ/road WA）**，均为条件遗漏类型；
- 任务二要求的 **4 项能力均可落地**；定位准确率 80%、误报率 62.5%、巧合召回 100%，反映评估器真实能力边界；
- **评估方式**：HY3 裁判通过 WorkBuddy 人工评估工作包独立运行（非自答自评），裁判与 gold 存在真实分歧；误报率偏高主要源于验证样本 process_text 过简，生产题评估因提供题面全文而表现稳定。
- **过程正确率 50.0%**（4/8）；HY3 能力边界起于**普及级基础题中的条件遗漏**（circular），在**竞赛级难题**（replace/employ/road）全面暴露（见 5.8）。
- demo 视频：demo.mp4（99 秒，带字幕）已纳入项目根目录。

### 5.8 难度临界点分析（模型能力边界）

任务书要求「按难度分层分析，指出模型表现开始明显下降的难度区间」。结合第三章（答案准确率）与本章（过程评估）：

- **基础题区间（普及− ~ 普及：number / seat / club / xor / circular）**：HY3 全部满分，过程均成立，无能力短板。
- **临界点 ≈ 提高难度（road, CSP-S B）**：road 过程声称「对乡镇建模求 MST」但实际仅做基础 MST、忽略乡镇，过程–代码不一致导致 WA（得分 32）；该题为 HY3 首个出现**过程层面**错误的节点。
- **竞赛级难题（replace / employ，提高+ / 省选− ~ 省选 / NOI−）**：replace 推理成立但 O(n·L) 朴素比较在大数据点 TLE（效率局限）；employ 以 `n>10 → 0` 简化替代完整解，条件遗漏导致 WA（得分 12）。此区间 HY3 的**过程正确率进一步下降**（3/4 过程不成立）。

**结论**：HY3 的能力边界落在「提高难度」起步、在「竞赛级难题」全面暴露；过程评估在此区间捕获的错误类型以**条件遗漏**（未实现一般情形）与**效率 / 规模局限**为主，与答案准确率层面的 TLE / WA 表现一致。
